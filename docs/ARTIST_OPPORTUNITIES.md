# Artist Opportunities

Opportunities is the third navigation mode in Hangabout. It uses the existing Vite app, URL history, visual styles, GitHub Actions and GitHub Pages. See Art and Make Art retain their existing datasets and discovery behaviour. Opportunity deep links use `#opportunity-<id>` and work under the Pages base path. Filters run in the browser without accounts, tracking or disclosure of personal eligibility information.

## Directory discovery pilot

No public feed or API was advertised there. The adapter checks that one index every seven days on schedule. The refresh artifact lists each unique lead and any catalogue IDs matched through explicitly reviewed discovery provenance. The directory's editorial criteria cover international mobility. Review each programme's eligibility, funding, fees and dates with its organiser before publishing.

The first extraction found 26 residency links. On the Move points to the [Emmanuel College residency programme](https://www.ecartistresidency.com/). The [college's application guidelines](https://www.ecartistresidency.com/apply) establish international eligibility, a USD 1,500 stipend, conditional travel and visa support up to USD 1,000, and supplied lodging. The catalogue records the separate On the Move link as discovery provenance for this round.

## Source activation and changes

Before enabling a source, verify its canonical public pages, source terms, robots directives, applicant geography and programme relevance. Inspect APIs, feeds and structured metadata before implementing page extraction. The active pages exposed the necessary evidence in public HTML. The Wyndham, Createability and Down the Lane adapters discover dated round pages from official indexes. Most other adapters monitor reviewed programme URLs and create new records when those pages publish a new round. Inspect the source registry for reviewed dates, coverage and fetch cadence.

The Python standard-library fetcher checks robots directives, applies crawl delay, enforces time and response-size limits, retries transient failures and stops on access restrictions or redirects. Third-party application portals are linked from public funder evidence. The job does not fetch authenticated application forms. Keep summaries in Hangabout’s words and publish only the facts needed for discovery.

The versioned catalogue holds first-party links, discovery provenance, timing, financial terms, eligibility and editorial fields. Null means a detail has not been established for the record. Explicit zero fees require evidence and remain distinguishable from null. Programmes with a shared page have separate round or stream keys. Where a provider publishes no round number, the adapter uses the deadline’s year and month. A cross-month rescheduling or domain migration needs a reviewed identity reconciliation. Review explicit URL aliases for cross-source matching and retain the initial ID and original funder provenance. Similar titles alone are insufficient.

A failed fetch or incompatible extraction leaves the latest valid records intact. A successful check that no longer lists a round retains it and makes its verification stale. A returning round can recover the same ID. Changes to extracted facts or normalized source text appear in the review report. When terms change beyond the mapped fields, review the official page and update the adapter where needed before accepting the proposal. Open badges require fresh, first-party evidence. The client expires precise deadlines in the published zone and hides application actions once closed, suspended or overdue. A dated announcement without an opening date stays forthcoming until new evidence arrives or the deadline passes.

## Scheduled operation and release

`.github/workflows/opportunity-refresh.yml` checks due sources daily on main and retains a source-health report and proposed data patch for 30 days. The report records source failures, quarantined observations and the last successful fetch. When a request returns an HTTP error, it reports the failed URL. Unchanged source checks do not create daily data churn. Periodic verification proposals renew the public checked date before records become overdue. Only a scheduled main run can open a draft review PR, and the workflow keeps at most one open proposal at a time. Review the diff and first-party links, then use the project’s normal merge and Pages verification flow. Pull request and manual checks are read-only in GitHub.

The pipeline uses a one- to seven-day source cadence. It introduces no paid API, model, database, npm or Python dependency. It uses existing Actions minutes, artifact retention and Pages hosting. The schedule is registered once the workflow reaches the default branch. Roll back code and catalogue changes by reverting the feature PR through the normal review flow. To pause proposals while retaining the UI, disable the workflow. To pause an individual source, move its registry entry to a reviewed inactive state and retain its validated records.
